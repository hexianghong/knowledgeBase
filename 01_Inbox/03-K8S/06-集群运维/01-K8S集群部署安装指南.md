# ☸️ Kubernetes 集群部署与安装指南 (Containerd & Docker 双方案)

在生产环境中搭建 Kubernetes 集群，必须经过规范的主机系统调优、容器运行时部署、以及引导组件配置。本文提供一套基于 **Kubeadm** 的集群安装实战指南，涵盖现代主流的 **Containerd 运行时 (v1.25+)** 方案与传统的 **Docker + Dockershim (v1.20)** 兼容方案。

---

## 一、 系统基础环境准备 (所有节点执行)

在部署任何容器运行时和 K8S 组件之前，必须对宿主机操作系统进行以下底层配置，以确保控制面与节点服务的高可靠运行。

### 1. 系统时区与时间同步
Kubernetes 集群的组件通信、证书校验以及日志分析对时间同步有极严格的要求。时间偏差过大会导致 API 证书失效或 etcd 集群脑裂。
```bash
# 1. 安装 chrony 时间同步服务
yum install chrony -y
systemctl enable --now chronyd

# 2. 设置系统时区为 亚洲/上海
timedatectl set-timezone Asia/Shanghai
# 将当前的 UTC 时间写入硬件时钟
timedatectl set-local-rtc 0

# 3. 强制触发一次同步并重启依赖于系统时间的服务
chronyc sources -v
systemctl restart rsyslog 
systemctl restart crond
```

### 2. 主机配置与防火墙、Selinux 关闭
```bash
# 1. 禁用防火墙
systemctl disable --now firewalld

# 2. 禁用 SELinux (必须永久生效，否则 Kubelet 无法访问宿主机文件系统)
setenforce 0
sed -i 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config

# 3. 禁用 Swap 分区 (K8S 调度器要求物理内存 100% 可控，避免内存交换带来严重的延迟)
swapoff -a
sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# 4. 配置本地 /etc/hosts 解析 (替换为您的实际 IP)
cat << EOF >> /etc/hosts
172.16.251.101 kube-master-01
172.16.251.102 kube-master-02
172.16.251.103 kube-master-03
172.16.251.110 VIP                          # 控制面虚拟 IP
172.16.251.104 kube-node-01
172.16.251.105 kube-node-02
172.16.251.106 kube-node-03
172.16.251.107 harbor.rubikstack.com
EOF
```

### 3. Linux 内核转发与网桥过滤参数
启用网桥的过滤功能以及 IPv4 转发，确保网桥的数据包通过 iptables 过滤，这是 CNI 网络插件能够正常通信的物理基础。
```bash
# 1. 写入 sysctl 配置文件
cat << EOF > /etc/sysctl.d/k8s-sysctl.conf
net.bridge.bridge-nf-call-ip6tables = 1
net.bridge.bridge-nf-call-iptables = 1
net.ipv4.ip_nonlocal_bind = 1
net.ipv4.ip_forward = 1
vm.swappiness = 0
vm.max_map_count = 655360
kernel.pid_max = 500000
EOF

# 2. 手动加载 br_netfilter 模块
modprobe br_netfilter

# 3. 应用内核参数
sysctl -p /etc/sysctl.d/k8s-sysctl.conf
```

### 4. 安装并配置 IPVS 负载均衡内核模块
Kube-Proxy 在 IPVS 模式下的转发性能比 Iptables 高出数倍（特别是在 Service 数量庞大的生产集群）。
```bash
# 1. 安装管理依赖包
yum install -y ipset ipvsadm

# 2. 配置开机自动加载 IPVS 相关内核模块的脚本
cat << 'EOF' > /etc/sysconfig/modules/ipvs.modules
#!/bin/bash
modprobe -- ip_vs
modprobe -- ip_vs_rr
modprobe -- ip_vs_wrr
modprobe -- ip_vs_sh
modprobe -- nf_conntrack
modprobe -- br_netfilter
EOF

# 3. 执行脚本加载模块并配置权限
chmod 755 /etc/sysconfig/modules/ipvs.modules
bash /etc/sysconfig/modules/ipvs.modules

# 4. 确认模块成功加载
lsmod | grep -e ip_vs -e nf_conntrack
```

## 二、 现代容器运行时 Containerd 部署 (K8S 1.22+ 推荐方案)

从 v1.24 开始，Kubernetes 彻底移除了 Dockershim。**Containerd** 作为轻量级、工业级的容器运行时底座，成为了 K8S 的首选 CRI。

### 1. 安装 Containerd
```bash
# 添加 Docker 官方 Repo 源 (Containerd 包含在此源中)
yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
yum makecache fast

# 安装 Containerd
yum install -y containerd.io
```

### 2. 配置 Containerd 核心参数
生成默认配置文件，并修改两个生产环境最为关键的设置：
1. **SystemdCgroup = true**：使得 Containerd 使用 systemd 进行 cgroup 管理。Kubelet 默认也使用 systemd，两者必须保持一致，否则 Kubelet 会周期性挂掉。
2. **Aliyun Sandbox Image**：在国内网络环境下，必须将 `sandbox_image` 从默认的 `registry.k8s.io` 更改为阿里云镜像源，否则 Pod 无法启动（Pause 容器无法拉取）。

```bash
# 1. 备份并生成默认 config.toml
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml

# 2. 修改配置 (SystemdCgroup 设为 true)
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml

# 3. 替换 sandbox 镜像源为国内阿里云加速源 (以 3.9 版本为例)
sed -i 's|sandbox_image = "registry.k8s.io/pause:3.6"|sandbox_image = "registry.aliyuncs.com/google_containers/pause:3.9"|g' /etc/containerd/config.toml
sed -i 's|sandbox_image = "registry.k8s.io/pause:3.8"|sandbox_image = "registry.aliyuncs.com/google_containers/pause:3.9"|g' /etc/containerd/config.toml

# 4. 重启 Containerd 并设置自启
systemctl daemon-reload
systemctl enable --now containerd
systemctl status containerd
```

## 三、 使用 Kubeadm 安装与引导 K8S 集群

### 1. 配置 Kubernetes 组件 YUM 源
```bash
cat >> /etc/yum.repos.d/kubernetes.repo << EOF
[kubernetes]
name=kubernetes
baseurl=https://mirrors.aliyun.com/kubernetes/yum/repos/kubernetes-el7-x86_64
enabled=1
gpgcheck=0
repo_gpgcheck=0
gpgkey=https://mirrors.aliyun.com/kubernetes/yum/doc/yum-key.gpg
       https://mirrors.aliyun.com/kubernetes/yum/doc/rpm-package-key.gpg
EOF
```

### 2. 安装 Kubeadm、Kubelet 和 Kubectl
以 1.25 版本为例（若要部署其他版本，如 1.28，可修改版本号后缀）：
```bash
# 安装指定版本
yum install -y kubelet-1.25.0 kubeadm-1.25.0 kubectl-1.25.0 --disableexcludes=kubernetes

# 启动并使能 Kubelet 开机启动 (此时因未 init 状态为 active (waiting))
systemctl enable --now kubelet
```

### 3. 高可用控制面配置 (kube-vip，单 Master 忽略此步)
在多控制面架构中，必须提供负载均衡器来代理 API Server 请求。**Kube-vip** 可以直接以静态 Pod 形式部署在 Master 节点上，通过虚拟 IP (VIP) 实现高可用路由。
```bash
# 声明虚拟 VIP 和对应网卡
export VIP=172.16.251.110
export INTERFACE=eth0

# 创建静态 Pod 定义目录
mkdir -p /etc/kubernetes/manifests/

# 通过官方容器拉取静态 Pod 定义并生成文件
docker run --rm plndr/kube-vip:v0.5.5 manifest pod \
  --interface $INTERFACE \
  --vip $VIP \
  --controlplane \
  --services \
  --arp \
  --leaderElection | tee /etc/kubernetes/manifests/kube-vip.yaml
```

### 4. 声明初始化配置文件 (kubeadm-config.yaml)
在引导之前，使用配置文件声明初始化参数，以配置国内镜像源、IPVS 模式和集群子网。

```yaml
# kubeadm-config.yaml
apiVersion: kubeadm.k8s.io/v1beta3
kind: ClusterConfiguration
kubernetesVersion: v1.25.0
imageRepository: registry.aliyuncs.com/google_containers # 使用阿里云镜像源
controlPlaneEndpoint: "172.16.251.110:6443"              # 高可用 VIP 地址 (单主写主节点 IP)
networking:
  podSubnet: "10.43.0.0/16"                              # Pod 的 CIDR 网段
  serviceSubnet: "10.96.0.0/12"                          # Service 的 CIDR 网段
apiServer:
  extraArgs:
    authorization-mode: "Node,RBAC"
controllerManager:
  extraArgs:
    bind-address: "0.0.0.0"
scheduler:
  extraArgs:
    bind-address: "0.0.0.0"
---
apiVersion: kubeproxy.config.k8s.io/v1alpha1
kind: KubeProxyConfiguration
mode: ipvs                                               # 强制开启 IPVS 转发模式
```

### 5. 执行引导与凭证分发
```bash
# 1. 预先拉取所需镜像
kubeadm config images pull --config=kubeadm-config.yaml

# 2. 执行集群初始化
kubeadm init --config=kubeadm-config.yaml --upload-certs | tee kubeadm-init.log

# 3. 配置当前普通用户或 root 的 Kubectl 鉴权凭证
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### 6. Node 节点加入集群
在 `kubeadm init` 成功后的输出日志尾部，会包含形如下方的 Join 命令：
```bash
# 1. Worker 节点加入集群命令示例
kubeadm join 172.16.251.110:6443 --token vfa3nb.2r4vk13jb34twild \
  --discovery-token-ca-cert-hash sha256:237e1c9b057bb4d454c9cb97ae5d180381bbeb622dd83af9941ba258eeffc80b

# 2. 控制面副本 (其他 Master) 加入集群命令示例 (带 --control-plane)
kubeadm join 172.16.251.110:6443 --token vfa3nb.2r4vk13jb34twild \
  --discovery-token-ca-cert-hash sha256:237e1c9b057bb4d454c9cb97ae5d180381bbeb622dd83af9941ba258eeffc80b \
  --control-plane --certificate-key 26816d54c5bdc85bbc815097d59417d7e65bf7be9477f7da8331c2dfb712ab3c
```

### 7. 部署 Calico 网络插件
```bash
# 1. 获取官方资源清单
wget https://docs.projectcalico.org/manifests/calico.yaml

# 2. 检查并修改配置文件中的 Pod 网段参数，确保与 kubeadm-config.yaml 中的 podSubnet 对齐
# 找到下述字段并取消注释：
# - name: CALICO_IPV4POOL_CIDR
#   value: "10.43.0.0/16"

# 3. 如果系统存在多块物理网卡，建议设置网卡自动侦测方法，避免流量绑定错误网卡：
# - name: IP_AUTODETECTION_METHOD
#   value: "interface=ens32"  # 替换为您的主要物理网卡名 (例如 eth0 或 ens32)

# 4. 部署网络插件
kubectl apply -f calico.yaml

# 5. 查看网络 Pod 状态直至全部 Running
kubectl get pods -n kube-system -w
```

## 四、 传统兼容方案：Docker + Dockershim 部署 (K8S 1.20 时代)

若需要在遗留项目或 CentOS 7 机器上维护 v1.20 或更低版本的旧集群，可选用此方案。

### 1. 系统内核升级 (CentOS 7 升级至长期支持内核 5.4.x)
CentOS 7 默认的 3.10 内核存在严重的内存泄漏缺陷（特别是在 Cgroup 频繁创建销毁的容器场景下），必须对其升级。
```bash
# 1. 定义 elrepo-kernel 源
cat << EOF > /etc/yum.repos.d/elrepo.repo 
[elrepo]
name=ELRepo.org Community Enterprise Linux Repository – el7
baseurl=https://mirrors.ustc.edu.cn/elrepo/elrepo/el7/\$basearch/
enabled=1
gpgcheck=0
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-elrepo.org
protect=0

[elrepo-kernel]
name=ELRepo.org Community Enterprise Linux Kernel Repository – el7
baseurl=https://mirrors.ustc.edu.cn/elrepo/kernel/el7/\$basearch/
enabled=1
gpgcheck=0
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-elrepo.org
protect=0
EOF

# 2. 安装长期支持版内核 (kernel-lt)
yum --enablerepo=elrepo-kernel -y install kernel-lt

# 3. 设置新内核为开机默认启动
awk -F\' '$1=="menuentry " {print i++ " : " $2}' /etc/grub2.cfg
grub2-set-default 0
grub2-mkconfig -o /boot/grub2/grub.cfg

# 4. 重启系统以加载新内核
reboot
uname -r
```

### 2. 安装 Docker Engine (v19.03.15)
```bash
# 1. 安装前置工具
yum install -y yum-utils device-mapper-persistent-data lvm2

# 2. 添加 repo 并安装
yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
yum install -y docker-ce-19.03.15 docker-ce-cli-19.03.15 containerd.io
```

### 3. 配置 Docker 守护进程参数 (daemon.json)
```bash
# 核心关键：必须将默认的 cgroup 驱动修改为 systemd，并设置私有 Harbor 仓库信任地址
cat << EOF > /etc/docker/daemon.json
{
  "exec-opts": ["native.cgroupdriver=systemd"],
  "registry-mirrors": ["https://dockerproxy.com"],
  "oom-score-adjust": -1000,
  "insecure-registries": ["harbor.rubikstack.com"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "300m",
    "max-file": "10"
  },
  "max-concurrent-downloads": 10,
  "max-concurrent-uploads": 10
}
EOF

# 启动 Docker 并设置自启
systemctl daemon-reload
systemctl restart docker
systemctl enable docker
```

### 4. 安装 K8S 1.20 组件并初始化
```bash
# 安装 1.20.15 版本的 K8S 引导程序
yum install -y kubeadm-1.20.15 kubelet-1.20.15 kubectl-1.20.15
systemctl enable --now kubelet

# 单节点初始化命令
kubeadm init \
  --apiserver-advertise-address=172.16.251.101 \
  --image-repository registry.aliyuncs.com/google_containers \
  --kubernetes-version v1.20.15 \
  --service-cidr=10.96.0.0/12 \
  --pod-network-cidr=10.43.0.0/16 \
  --ignore-preflight-errors=all
```

## 五、 Kubectl 命令行自动补全设置

配置快捷补全能显著提升在集群运维过程中的敲击效率与准确度。

```bash
# 1. 确保安装了系统补全底座包 (必配，否则会报 _get_comp_words_by_ref 错误)
yum install -y bash-completion

# 2. 如果您当前使用的是 Bash Shell：

echo "source <(kubectl completion bash)" >> ~/.bashrc

# 3. 如果您当前使用的是 Zsh Shell：
source <(kubectl completion zsh)
echo "source <(kubectl completion zsh)" >> ~/.zshrc
source ~/.zshrc
```

## 六、 企业级离线多 Master 高可用全自动部署实战 (基于华卓离线套件)

在银行、医疗、军工等全隔离无外网机房中，无法通过外网镜像源或公网 Yum 仓库安装。本方案提供一套基于**华卓离线高可用部署套件**的完整生产交付规范，集成 **Keepalived + HAProxy 双层高可用网关**、**Containerd 存储层软链解耦**、**Calico IPIP 网络**、**Local-Path 动态存储**、**Metrics-Server** 与 **100 年长效证书**。

### 1. 离线部署套件目录结构
```text
k8s-install-offline-centos/
├── install.conf.template         # 全局部署配置文件模板
├── k8s-offline-optimized.sh      # 主控部署核心脚本 (支持 100% 幂等重入)
├── k8s-node-add-optimized.sh     # Worker 节点动态扩容脚本 (自动计算编号与刷新 Token)
├── k8s-test.sh                   # 集群 8 项生产级健康度全自动巡检脚本
├── nginx/
│   ├── nginx-1.24.0.tar.gz       # 离线 Nginx 源码包
│   ├── nerdctl                   # Containerd 客户端调试二进制
│   ├── local-yum-repo/           # 全量离线 RPM 依赖软件仓
│   └── nginx-Packages/           # 编译工具链 RPM 包 (gcc, make 等)
├── image/
│   ├── image.zip                 # K8S 核心组件、Calico、Pause:3.7、Metrics 离线镜像包
│   └── image_load.sh             # 镜像自动解压与 nerdctl 批量导入脚本
└── conf/
    ├── config.toml               # 经过 3 轮精化的生产级 Containerd 配置
    ├── k8s.conf                  # 系统内核转发与网桥优化参数
    ├── limits.conf               # 文件描述符与线程数限制 (655360)
    ├── check_apiserver.sh        # Keepalived 健康检查与故障自愈脚本
    ├── kubeadm                   # 重新编译定制的 100 年证书 kubeadm 二进制
    ├── calico.yaml               # Calico CNI 清单文件 (CALICO_IPV4POOL_CIDR 对齐)
    ├── local-path-storage.yaml   # 本地持久化存储类清单文件 (/data/local-path)
    ├── Metrics-Server.yaml       # 资源度量监控清单文件
    └── ingress-nginx-v1.3.1-daemonset-master.yaml # 七层 Ingress 控制器清单
```

### 2. 准备全局配置文件 `install.conf`
在主控节点 Master01 上复制模板并填写环境信息：
```bash
cp install.conf.template install.conf
vim install.conf
```

**`install.conf` 核心参数配置样例**：
```bash
# 1. 所有节点统一的 root 用户 SSH 密码
COMMON_PASSWORD="YourSecurePassword123!"

# 2. Master 与 Node IP 列表 (以空格分隔)
MASTER_IPS=("172.16.255.191" "172.16.255.192" "172.16.255.193")
NODE_IPS=("172.16.255.194" "172.16.255.195")

# 3. 控制面高可用 VIP 地址与代理端口
VIP_VALUE="172.16.255.190"
VIP_PORT="16443"

# 4. 时间同步服务器 (留空则以 Master01 作为本地 NTP 根源)
DATE_SERVER=""

# 5. 容器数据存储目录 (软链接至大容量数据盘，防止擦爆系统盘)
CONTAINERD_DATA_DIR="/data/containerd"

# 6. Pod 与 Service 网段
POD_SUBNET="10.244.0.0/16"
SERVICE_SUBNET="10.96.0.0/12"
```

### 3. 一键非交互式部署
```bash
chmod +x k8s-offline-optimized.sh
./k8s-offline-optimized.sh
```
脚本自动完成：
1. 本地 Nginx YUM 源编译拉起（端口 `48080`）与 Chrony 毫秒级时间同步；
2. 批量 SSH 免密建立与系统环境加固（关闭 Swap/Firewalld/SELinux，加载 IPVS/br_netfilter）；
3. 存储解耦（建立 `/data/*` 软链接）、Containerd 安装与离线镜像载入；
4. Keepalived + HAProxy 双层高可用网关拉起与 VIP 连通性自检；
5. 深度前置环境体检（EUID、SSH、时钟偏差 $\le 2\text{s}$、CPU/内存/磁盘、端口冲突）；
6. `kubeadm init` 初始化控制面并分发 Token 自动接入从 Master 与 Worker 节点；
7. 部署 Calico、Local-Path、Metrics-Server、Ingress 并升级 Kube-Proxy 为 IPVS 模式；
8. 替换定制 `kubeadm`，全量更新集群证书有效期为 **100 年**。

### 4. 动态扩容新计算节点
当集群需要新增机器时，在 Master01 上执行：
```bash
chmod +x k8s-node-add-optimized.sh
./k8s-node-add-optimized.sh
```
* **智能命名**：自动读取集群现有 Worker 数量，主机名自动按 `kube-node-(N+1)` 顺序递增；
* **动态 Token**：实时调用 `kubeadm token create` 生成全新加入凭证，杜绝 24 小时过期失效；
* **全局路由刷新**：节点加入后自动重新生成包含新节点的 `/etc/hosts` 并全网同步。

### 5. 集群生产健康度全自动巡检
部署或扩容后，运行巡检脚本验证集群：
```bash
chmod +x k8s-test.sh
./k8s-test.sh
```
脚本将自动执行 8 大维度的全链路体检，涵盖节点状态、核心静态 Pod、CoreDNS 域名解析、IPVS 规则拓扑、Local-Path 动态卷实际读写、Metrics 指标接口以及 100 年证书有效天数。

## 七、 离线生产故障快速排查与排障清单

| 故障现象 | 根因定位 | 快速修复命令与方案 |
| :--- | :--- | :--- |
| **`unknown service runtime.v1.RuntimeService`** | containerd 默认配置禁用了 cri 插件 | `sed -i 's/.*disabled_plugins.*/disabled_plugins = []/g' /etc/containerd/config.toml && systemctl restart containerd` |
| **离线 YUM 仓抛出 404 Not Found** | Nginx 配置中 `root` 指向路径与实际离线包解压路径不符 | 检查 `/etc/nginx/conf/nginx.conf` 中的 root 路径，执行 `/etc/nginx/sbin/nginx -s reload` |
| **高可用 VIP 无法 ping 通或 16443 超时** | Keepalived 未绑定正确物理网卡或 HAProxy 进程挂掉 | 检查 `ip addr show`，排查 `systemctl status keepalived` 与 `systemctl status haproxy` |
| **Pod 一直处于 `ContainerCreating`** | 离线环境无法在线拉取 Pause 镜像 | 确认 `config.toml` 中 `sandbox_image` 指向已载入的 `pause:3.7`，运行 `nerdctl -n k8s.io images` 查看 |
| **节点加入时报 Token Expired** | 使用了超过 24 小时的旧 Token | 在 Master01 执行 `kubeadm token create --print-join-command` 生成新 Token 后重新 Join |
