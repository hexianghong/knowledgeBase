- **影响范围**：[是否停服、是否影响只读、预期闪断时间]

## 2. 操作前置检查清单 (Pre-flight Checklist)

- [ ] 1. 确认已完成全量物理备份并校验 MD5：`/backup/...`
- [ ] 2. 检查各节点磁盘剩余空间 > 50GB：`df -h`
- [ ] 3. 检查当前主从复制/集群延迟为 0：`Seconds_Behind_Master: 0`
- [ ] 4. 检查当前业务活跃连接与长事务：`SHOW PROCESSLIST`
- [ ] 5. 确认回滚方案与应急脚本就绪。

---

## 3. 标准操作执行步骤 (Step-by-Step Execution)

### 步骤 1：业务流量切断 / 隔离
```bash
# 执行隔离命令
systemctl stop mysqlrouter
```

### 步骤 2：核心变更操作
```bash
# 核心操作步骤
sh execute_upgrade.sh
```

### 步骤 3：数据与状态核验
```bash
# 验证状态指令
cluster.status()
```

### 步骤 4：恢复业务流量
```bash
# 恢复流量
systemctl restart mysqlrouter
```

---

## 4. 操作验收标准 (Verification Criteria)

1. **服务端口与进程**：3306 / 6446 正常监听且无异常崩溃日志。
2. **集群拓扑状态**：所有节点均为 `ONLINE`，无分歧与报错。
3. **业务读写拨测**：执行模拟读写 SQL 返回正常。

---

## 5. 应急回滚预案 (Rollback Plan)

> [!CAUTION]
> **触发回滚条件**：操作超过预定窗口仍未恢复 / 发生致命数据损坏 / 主节点无法启动。

1. **执行快速回滚**：
   ```bash
   sh rollback.sh
   ```
2. **还原数据目录**：
   ```bash
   rm -rf /app/data/* && cp -a /backup/pre_change_data/* /app/data/
   ```
3. **拉起服务并通报**：恢复旧版本实例，通知相关业务方。
