# MySQL 故障排查与性能调优终极指南（小白秒懂版）

欢迎查阅这份**集合了 100+ 真实企业级故障场景**的终极百科全书！
这份文档经过“多重虚拟 DBA Agent”的 20 轮深度学习与扩展，将枯燥深奥的数据库底层原理转化为**通俗易懂的生活比喻**，让你哪怕是刚接触数据库的“小白”，也能循序渐进地掌握大厂级别的故障排查与性能调优能力。

## 📖 设计理念与阅读指北

为方便系统性学习与日常检索，本指南被拆分为 6 个核心子文档。每个子文档中的每一个故障点，都严格遵循以下六步闭环结构：

1. 🌟 **小白秒懂（通俗比喻）**：用最生活化、最接地气的例子解释为什么会发生故障。
2. 🚩 **故障现象（错误长啥样）**：直观展示应用层或日志里弹出的报错信息，方便你用报错信息全文搜索匹配。
3. 🕵️ **根本原因（底层逻辑）**：深入浅出的技术原理解析，带你知其所以然。
4. 🛠️ **排查步骤（手把手敲命令）**：提供可以直接复制粘贴在终端执行的 SQL 诊断脚本及命令，并教你怎么看懂查出来的结果。
5. 💊 **解决方案（对症下药）**：提供“紧急止血方案”（线上出事了马上救命）和“长效优化方案”（彻底根治）。
6. 🛡️ **避坑指南（防患于未然）**：总结最佳实践与研发规范，教你如何在开发写代码的阶段就避开这些坑。

### [第一部分：SQL 性能与索引优化篇 (点击进入)](./01_SQL_And_Index_Optimization.md)

- 分页越查越慢怎么办？

### [第二部分：锁机制与并发控制篇 (点击进入)](./02_Locks_And_Concurrency.md)
**高并发大流量克星！** 如果你的系统一搞秒杀就死机，一定要看这里。涵盖内容：
- 行锁等待超时（Lock wait timeout）
- 死锁互相卡住（Deadlock found）
- 表元数据锁阻塞全表（Metadata lock）
- 幻读与并发超卖问题解决

### [第三部分：InnoDB 存储引擎与物理磁盘篇 (点击进入)](./03_InnoDB_Storage_And_Disk.md)
**DBA 抢修手册！** 应对磁盘打满、表损坏等硬核问题：
- 磁盘空间 0 字节，服务崩溃
- 表空间膨胀缩不回来
- 单表体积巨大导致 I/O 瓶颈
- Redo Log 与大对象处理

### [第四部分：系统资源与内核调优篇 (点击进入)](./04_System_Resource_And_Kernel.md)
**压榨服务器最后一点性能！** 解决莫名其妙的卡顿：
- 内存溢出（OOM）被系统强杀
- CPU 飙升 100% 卡死
- Swap 交换引发的极度缓慢
- Buffer Pool 与系统缓存配置优化

### [第五部分：主从复制与 MGR 高可用集群篇 (点击进入)](./05_Replication_And_MGR.md)
**分布式系统排雷指南！** 专门针对多节点架构：
- 主从延迟（Seconds_Behind_Master 暴涨）
- 从库复制中断（Error 1062 / 1032）
- MGR 脑裂、多写冲突与网络分区
- 大事务拖垮整个集群

### [第六部分：连接、网络、日志与备份运维篇 (点击进入)](./06_Ops_Network_And_Backup.md)
**基础设施健康指南！** 运维同学的好帮手：
- 连接数爆满（Too many connections）

- 数据包超限报错（max_allowed_packet）
- 安全、审计日志与备份崩溃恢复
